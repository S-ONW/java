# 2026-11-11

## 优惠券接入数据库（新建 coupon 表）

需求：ticket 池原来是前端 `data.js` 的 `COUPON_POOL` 写死的，只把「谁领了哪张券」存 `user_coupon` 表。
现在把**券池本身**也落库，新建 `coupon` 表，后台增删改直接写数据库。

### 数据库
- 新表 `coupon`：`id / code(唯一) / title / descp / type(pct|fix) / val / min_amount / create_time`。
- 三处 SQL 同步：`sql/shop.sql`（dump 风格 DROP/CREATE + 6 条记录）、
  `resources/db/schema.sql`（`CREATE TABLE IF NOT EXISTS`，启动幂等执行）、
  `resources/db/data.sql`（`INSERT IGNORE` 6 张种子券）。
- **折扣语义（重要，别再搞反）**：`type=pct` 时 `val` 是**减免比例**，`0.2` = 减 20% = **8 折**
  （结算 `小计 × val` 抵扣）。`amount`（「8 折」/「¥30」）和 `cond`（「满 199 可用」）都是**派生展示文案，不入库**，
  由 `type/val/min` 现算。原代码 admin 保存时用 `val*10` 算折数（0.2→「2 折」）是错的，已一并修正为 `(1-val)*10`。
- 本机 shop 库已实际建表 + 种子数据（6 张，id 1-6；`user_coupon` 原 2 条记录未动）；
  顺手把 `val` 列注释改成「pct 为减免比例（0.2=减20%即8折）」。

### 后端
- 新增 `entity/Coupon.java`、`mapper/CouponMapper.java`。
- `CouponService` 扩展成「券池 + 领券」双职责：`listPool/listPoolVO/findByCode/save/delete/toVO`，
  字段归一化 + 校验（券码 `^[A-Z0-9_]+$`、pct 0.01~1、min≥0、券码唯一）在 service 里，非法抛 `BusinessException`。
- `claim()` 增加校验：券池非空时，code 必须真实存在于 `coupon` 表，否则 409「不存在或已下架」
  （券池为空时不拦，兼容没建表的旧库）。
- `CouponController` 新增：`GET /api/coupon/pool`（公开）、`POST /api/coupon/admin/save`、
  `DELETE /api/coupon/admin/delete?code=`（后两个要 `X-Admin-Token`）。原 claim/list/grant/remove 不变。

### 前端
- `store.js`：券池唯一数据源仍是 `store.couponPool`；新增 `loadCouponPool()`（`/api/coupon/pool`），
  `adminSaveCoupon`/`adminDeleteCoupon` 改为 **async 走 `adminWrite` 写数据库**，成功后 `loadCouponPool()` 刷新；
  后端不可用 / 离线模式登录时回退本地（`saveCouponLocal` 等）；抽出 `normalizeCoupon()` 统一算 amount/cond。
- `App.vue` 启动时 `loadCouponPool()`；`CouponView` 进入时刷新券池；`AdminView` 进后台刷新券池 +
  `saveCoupon/removeCoupon` 改 await。
- **修掉一个原有 bug**：`couponValidate` 用 `x !== c` 做引用比较，但调用处传的是 `{...c}` clone，
  导致「编辑任何券都报『该券码已存在』」。改为 `couponValidate(c, original)` 用 original 排除自身。
- 后台表单提示文案改为「减免比例（0.01~1，如 0.2 = 减 20% 即 8 折）」。

### 坑 / 注意事项
- `INSERT IGNORE` 在 InnoDB 下**会消耗自增 id**，所以本机 `coupon` 表 AUTO_INCREMENT 已经跑到 16，正常现象。
- 同步 dist 时 `dist/register.html` 会覆盖 static 里的独立注册页：本次覆盖的是同一份「后端验证码」版本，
  只差主题色与标题（云购→萧逸）。以后同步前先确认 dist/register.html 没把验证码修复覆盖回旧版。
- 券池顺序 = `coupon.id ASC`，想调领券中心的展示顺序就是调 id / 排序字段。
- 启动后端时若日志报 "Port 51234 was already in use"，是 shell 里 `SERVER__PORT` 环境变量被 Spring 当成
  `server.port`（文档里的老坑）。`$env:SERVER__PORT=$null` 并显式传 `-Dspring-boot.run.arguments=--server.port=8081` 即可。
- 用 JDBC 临时库验证 SQL 脚本的方法可复用：按行拼语句、遇到以 `;` 结尾就执行（本项目脚本无存储过程，够用），
  验证完 DROP 临时库即可，不要碰真实 shop 库。

### 第六轮：吉祥物表情包接入（用户给的 5 连拍小头像图）

  按段中点等分 → 每格统一 79×79 画布 → 2x LANCZOS + UnsharpMask → 158×158 透明 PNG，
  输出到 `src/assets/mascot/{calm,dizzy,happy,wow,laugh}.png`。
- **关键教训（踩过一次坑）**：一开始用 `alpha = 离背景色的差值 × 系数` 抠白底，
  浅色皮肤被算成半透明，放到深色底上整张脸变黑。
  正确做法是从图片四边**洪水填充**找出外部背景（不碰被包围的内部白点，如眼白），
  只在边界一圈做去白反解 `C = (P - (1-a)*bg)/a`，实心区保持原色。
