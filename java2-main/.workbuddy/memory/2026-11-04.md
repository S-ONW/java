## 后台管理「添加/删除商品」功能

- 现象：用户反馈后台编辑功能缺“添加/删除商品”。
- 排查结论：功能在 `shopping-vue/src` 源码中已完整实现（AdminView.vue + store.js：
  adminSaveProduct / adminDeleteProduct / adminDeleteProducts；后端 ProductController
  提供 /api/product/save、/api/product/{id} DELETE、/api/product/batch）。
  但后端 `springBootTest/src/main/resources/static/` 提供的是**早于后台管理功能的旧构建**
  （打包 JS 中无 admin/新增商品 字样），导致「启动后端.bat」跑起来的页面看不到增删界面。
- 修复：在 `shopping-vue` 执行 `npm run build`，将 `dist/*` 复制到
  `springBootTest/src/main/resources/static/`（并清理旧哈希资源 index-BKPOVH3F.js / index-WJumLZbx.css）。
  新构建已含后台管理全部功能，index.html 引用新哈希。
- 重要约定：此项目后端启动后提供的是 `static` 里的静态构建，不是 Vite 源码。
  **任何前端改动后必须重新 build 并同步 dist 到后端 static 目录，否则改动不会生效。**
- 运行依赖：后端需 MySQL（localhost:3306/shop, root/123456）；若不可用，前端自动退化为离线模式
  （admin/admin123 登录，数据存 localStorage），增删仍可用。
- 后台入口：AppHeader 顶部「⚙️ 后台管理」按钮；管理员账号 admin / admin123（application-dev.properties 配置）。

## 后台「无法新增/编辑商品」真正根因（第二轮，重要）

- 现象：重新部署前端后，页面能看到后台界面，但点「保存」没反应 / 加不了也改不了商品。
- 实测：curl 调后端登录/列表/新增/编辑/删除全部 200，后端写链路本身没问题；
  CORS（WebConfig allowedHeaders("*")）也没问题。用旧/伪造 token 保存稳定返回
  `401 {"msg":"登录已失效，请重新登录后台"}` —— 这就是前端保存失败的表现
  （AdminView.save 里 res.ok=false 会把 msg 显示成 formErr，弹窗不关闭）。
- 根因：`AdminService` 的 token 是**内存态**（ConcurrentHashMap，4h TTL），
  服务重启即清空；且 pom.xml 带 `spring-boot-devtools`，用 `mvnw spring-boot:run`
  运行时文件变动会**自动重启**，token 频繁失效。
  而前端把 `store.admin`（含 token）持久化在 localStorage，启动时直接读回，
  `AdminView.onMounted` 原本只在 `!store.admin` 时跳登录页，`AppHeader.onAdmin`
  也只看 `store.admin` 真假 → 旧 token 失效后仍显示「已连接数据库」并直接进后台页，
  所有写操作 401 且无任何引导 = “编辑/新增不能用”。
- 修复（已落地并验证）：
  1) 后端 AdminController 新增 `POST /api/admin/check`（复用 AdminService.check）。
  2) `store.js`：新增 `adminCheck()`（进入后台前复核，401 自动续期）、
     统一 `adminWrite()`（写操作遇 401 → `adminRelogin()` 用 sessionStorage 里的
     `shopAdminCreds` 静默重登 → 用新 token 重试一次），
     三个写操作（save/delete/batch）全部改走 adminWrite；`adminLogout` 清除凭据。
  3) `AdminView.onMounted` 改为 async：校验失败才清空并跳登录页（不会死循环，
     AdminLogin 登录成功 go('admin')）。
- **关键约定（第二轮补充，比第一轮更准确）**：后端实际提供的是
  `springBootTest/target/classes/static/`（编译产物），不只是
  `src/main/resources/static/`。前端重新 build 后必须把 `shopping-vue/dist/*`
  同时同步到 **两处**（src/main/resources/static 与 target/classes/static），
  并清理两处旧哈希 assets，否则运行中的后端仍服务旧 JS（曾出现线上 404）。
- 启动后端务必用原生 `cmd.exe` / PowerShell 调 `mvnw.cmd`；在 Git Bash 里
  直接 `./mvnw` 或 `mvn` 会因 MSYS 路径转换报
  `找不到或无法加载主类 org.codehaus.plexus.classworlds.launcher.Launcher`。
- 验证数据已还原：product 表 18 条（id 1-18），与 db/data.sql 种子一致。

## 后台「点击编辑按钮无反应」真正根因（第三轮，最终定位）

- 现象：能进后台、能看到商品列表，但点「编辑」「新增商品」按钮无任何反应；
  点「删除」正常（因为删除走 window.confirm 浏览器原生弹窗）。
- 根因：**CSS 全局层叠冲突**。商城前台弹窗在全局 `src/style.css` 里定义了
  `.modal{position:fixed;...;display:none}` + `.modal.open{display:flex}`（DetailModal/AuthModal 等用）。
  后台 `AdminView.vue` 的编辑/新增弹窗结构是 `<div class="mask"><div class="modal">`，
  其 scoped 样式里的 `.modal` **只写了背景/圆角/padding，漏写了 display**。
  于是后台的 `.modal` 元素被全局 `.modal{display:none}` 命中 → 弹窗 DOM 已渲染
  （v-if 的 confirmEdit/showForm 都正确变 true）却永远不可见 → 表现即「点编辑无反应」。
- 修复：在 `AdminView.vue` scoped `.modal` 里显式加 `display:block;`
  （scoped 编译成 `.modal[data-v-xxx]`，特异性高于全局 `.modal`，即可覆盖）。
  重新 build 并同步 dist 到两处 static（src 与 target/classes），线上已引用新构建。
- **教训**：后台自建弹窗复用 `.modal` 类名时，务必显式写 display，否则被全局
  style.css 的前台 `.modal{display:none}` 覆盖。排查「点按钮无反应」且代码逻辑正确时，
  优先怀疑 CSS 层叠（display:none / z-index / pointer-events）而非 JS 逻辑。
