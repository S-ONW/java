## 用户权限体系改造（permission + 明文密码 + 后台门禁）

- `user` 表新增 `permission TINYINT NOT NULL DEFAULT 1`：**1 = 默认权限（注册用户）**，**0 = 管理员权限**。
  密码改为**明文存储、明文比对**（去掉 UserService 的 MD5）。
  已在线迁移本机 MySQL：旧 MD5('123456') → '123456'；新增内置管理员
  `admin@shop.local` / 昵称 `admin` / `admin123` / permission 0。
- SQL 三处同步：`sql/shop_db.sql`（全新安装）、`sql/shop.sql`（dump）、
  `sql/upgrade_user_permission.sql`（已有库手动升级）；`resources/db/schema.sql`
  用 information_schema + PREPARE 动态 SQL 做**幂等**自动升级（MySQL 8 不支持 ADD COLUMN IF NOT EXISTS）。
- 后端：`User` 加 permission；`UserService.register` 固定写 1、`login` 返回 permission；
  `AdminService` 不再读 `admin.username/password` 配置，改为查 user 表校验明文密码且 permission=0，
  权限 1 返回 403；token 绑定 userId，`check()` 每次重读库复核权限，降权立即踢出。
  `AdminController` 返回 nick/permission，403 透传 msg。
- 前端：`store.js` 导出 `isAdminUser`（computed：store.user.permission===0）、`go()` 拦截
  admin/adminLogin、logout 同步清 shopAdmin、本地账号表带 permission 且有离线内置管理员；
  `AppHeader` 的「⚙️ 后台管理」按钮 `v-if="isAdminUser"`；
  `App.vue` 的 isAdminView / watch、`AdminView.onMounted`、`AdminLogin.onMounted` 均加权限守卫；
  `AccountView` 展示当前权限。
- **沿用既有约定**：改前端后已 `npm run build` 并把 dist 同步到
  `src/main/resources/static` 与 `target/classes/static` 两处，删除旧哈希 assets。
- 已验证（curl）：普通用户 permission=1、管理员 permission=0、权限1登录后台 403、
  注册落库明文+权限1、降权后旧 token 失效、恢复后重新登录成功、静态页引用新构建。
  测试账号已清理，最终 user 表 6 行（5 个普通 + 1 个管理员）。
- **注意**：旧 localStorage 里的 `shopUser` 没有 permission 字段 → 看起来「后台按钮消失」，
  重新登录一次即可。离线模式的管理员也必须有 permission=0 的本地账号（内置 admin/admin123）。
- 工具坑：Git Bash 调 `cmd.exe /c mvnw.cmd` 被安全策略拦截；改用 PowerShell 工具执行
  `Set-Location ...; & .\mvnw.cmd compile` 正常。无 mysql CLI，可用 mysql-connector-j jar + Java 单文件直连。
- `shopping-vue/AI启动说明.md` 已补「用户权限约定」章节。

  「密码（MD5）」注释改成「密码（明文存储，不加密）」。临时库已删除。
